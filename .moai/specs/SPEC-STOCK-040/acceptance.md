# SPEC-STOCK-040 수용 기준 (Acceptance Criteria)

작성일: 2026-06-25
대상: AI 포트폴리오 코멘터리

각 AC의 주어는 "THE 시스템"이며, REQ 그룹별로 최소 1개 이상의 AC를 정의한다.
하단에 Given-When-Then BDD 시나리오·엣지 케이스 표·Definition of Done을 포함한다.

---

## 1. EARS 형식 수용 기준 (AC List)

### 1.1 코멘터리 생성 (REQ-CMNT-001~010)

- AC-001: WHEN 인증된 사용자가 본인 포트폴리오의 코멘터리를 요청하면, THE 시스템 SHALL 성과 요약·리스크 코멘트·섹터 코멘트·추천 문구를 포함한 한국어 코멘터리를 반환한다. (REQ-CMNT-001~005)
- AC-002: WHILE 포트폴리오에 보유 종목이 없으면, THE 시스템 SHALL AI를 호출하지 않고 보유 종목이 없음을 안내하는 코멘터리를 반환한다. (REQ-CMNT-006)
- AC-003: THE 시스템 SHALL 모든 코멘터리 응답에 투자 권유가 아님을 명시하는 면책 문구를 포함한다. (REQ-CMNT-007)
- AC-004: IF 리스크 데이터가 가용하지 않으면, THEN THE 시스템 SHALL 가용한 성과·섹터 데이터만으로 코멘터리를 생성한다. (REQ-CMNT-008)
- AC-005: THE 시스템 SHALL 코멘터리 분석 입력에 사용자 식별 정보를 포함하지 않는다. (REQ-CMNT-009)
- AC-006: THE 시스템 SHALL 코멘터리 응답에 분석 기준 시점 정보를 포함한다. (REQ-CMNT-010)

### 1.2 캐싱·호출 제한 (REQ-CMNT-011~015)

- AC-010: WHEN 동일 포트폴리오·동일 보유 구성으로 재요청이 들어오면, THE 시스템 SHALL AI를 재호출하지 않고 캐시된 코멘터리를 반환한다. (REQ-CMNT-011)
- AC-011: WHEN 캐시 보관 기간이 만료된 후 요청이 들어오면, THE 시스템 SHALL 코멘터리를 새로 생성한다. (REQ-CMNT-012~013)
- AC-012: WHEN 보유 구성이 변경된 후 코멘터리가 요청되면, THE 시스템 SHALL 변경된 상태를 반영한 코멘터리를 새로 생성한다. (REQ-CMNT-014)
- AC-013: IF 최소 생성 간격 이내에 재생성 요청이 들어오면, THEN THE 시스템 SHALL 가장 최근 코멘터리를 반환한다. (REQ-CMNT-015)

### 1.3 소유권·접근 (REQ-CMNT-020~025)

- AC-020: IF 인증되지 않은 요청이 들어오면, THEN THE 시스템 SHALL 코멘터리를 제공하지 않고 인증이 필요함을 알린다. (REQ-CMNT-020~021)
- AC-021: IF 요청자가 소유하지 않은 포트폴리오의 코멘터리를 요청하면, THEN THE 시스템 SHALL 해당 포트폴리오를 찾을 수 없음을 알린다. (REQ-CMNT-022~023)
- AC-022: IF 존재하지 않는 포트폴리오의 코멘터리를 요청하면, THEN THE 시스템 SHALL 해당 포트폴리오를 찾을 수 없음을 알린다. (REQ-CMNT-024)
- AC-023: THE 시스템 SHALL 코멘터리 응답에 다른 사용자의 포트폴리오 정보를 노출하지 않는다. (REQ-CMNT-025)

### 1.4 오류 복구 (REQ-CMNT-030~035)

- AC-030: IF AI 코멘터리 생성이 실패하면, THEN THE 시스템 SHALL 사전 정의된 대체 코멘터리를 정상 응답 형식으로 반환한다. (REQ-CMNT-030, 034)
- AC-031: IF AI 응답 대기 시간이 허용 한도를 초과하면, THEN THE 시스템 SHALL 대기를 중단하고 대체 코멘터리를 반환한다. (REQ-CMNT-031)
- AC-032: WHEN AI 코멘터리 생성이 실패하면, THE 시스템 SHALL 실패 사실을 기록한다. (REQ-CMNT-032)
- AC-033: IF AI 응답이 기대한 형태로 해석되지 않으면, THEN THE 시스템 SHALL 유효한 부분만 추출하거나 대체 코멘터리를 반환한다. (REQ-CMNT-033)
- AC-034: IF AI 자격 증명이 설정되지 않은 환경에서 코멘터리가 요청되면, THEN THE 시스템 SHALL 대체 코멘터리를 반환한다. (REQ-CMNT-035)

### 1.5 비기능 (NFR)

- AC-NFR-001: THE 시스템 SHALL 코멘터리 본문을 한국어로 출력한다. (REQ-CMNT-NFR-001)
- AC-NFR-002: THE 시스템 SHALL 캐시 적중 시 AI 호출 없이 응답한다. (REQ-CMNT-NFR-002)
- AC-NFR-003: THE 시스템 SHALL 단일 코멘터리 생성에 사용하는 AI 응답 분량을 상한 이내로 제한한다. (REQ-CMNT-NFR-003)
- AC-NFR-004: THE 시스템 SHALL AI 응답 대기 시간을 상한 이내로 제한한다. (REQ-CMNT-NFR-004)
- AC-NFR-005: THE 시스템 SHALL 코멘터리 기능을 위해 신규 데이터베이스 테이블을 도입하지 않는다. (REQ-CMNT-NFR-005)

## 2. Given-When-Then BDD 시나리오

### 시나리오 1: 정상 코멘터리 생성

- Given: 인증된 사용자가 보유 종목 3개(국내 2 + 해외 1)를 가진 본인 포트폴리오를 보유한다.
- When: 사용자가 해당 포트폴리오의 코멘터리를 요청한다.
- Then: 시스템은 성과 요약·리스크 코멘트·섹터 코멘트·추천 문구·면책 문구를 포함한 한국어 코멘터리를 반환한다.

### 시나리오 2: 캐시 적중

- Given: 직전에 코멘터리가 생성된 포트폴리오의 보유 구성이 변경되지 않았다.
- When: 보관 기간 이내에 동일 포트폴리오의 코멘터리를 재요청한다.
- Then: 시스템은 AI를 재호출하지 않고 동일한 코멘터리를 반환하며 캐시 적중임을 표시한다.

### 시나리오 3: 보유 구성 변경 후 재생성

- Given: 포트폴리오에 신규 보유 종목이 추가되었다.
- When: 사용자가 코멘터리를 요청한다.
- Then: 시스템은 변경된 구성을 반영한 새 코멘터리를 생성한다.

### 시나리오 4: AI 실패 시 대체 응답

- Given: AI 자격 증명이 없거나 AI 호출이 실패하는 환경이다.
- When: 사용자가 코멘터리를 요청한다.
- Then: 시스템은 사전 정의된 대체 코멘터리를 정상 응답 형식(면책 문구 포함)으로 반환하고 실패를 기록한다.

### 시나리오 5: 소유권 위반

- Given: 사용자 A가 사용자 B의 포트폴리오 id로 코멘터리를 요청한다.
- When: 요청이 처리된다.
- Then: 시스템은 포트폴리오를 찾을 수 없음을 알리고 B의 정보를 노출하지 않는다.

### 시나리오 6: 빈 포트폴리오

- Given: 보유 종목이 없는 포트폴리오가 존재한다.
- When: 사용자가 코멘터리를 요청한다.
- Then: 시스템은 AI를 호출하지 않고 보유 종목이 없음을 안내하는 코멘터리를 반환한다.

## 3. 엣지 케이스

| 케이스 | 입력 조건 | 기대 동작 |
|--------|-----------|-----------|
| 단일 종목 | 보유 종목 1개 | 코멘터리 생성(리스크 분산 데이터 부족 시 베스트에포트) |
| 리스크 데이터 부족 | 유효 종목 2개 미만 | 성과·섹터만으로 코멘터리 생성 (리스크 코멘트는 데이터 한계 안내) |
| AI 응답 비정형 | JSON 아닌 응답 | 유효 부분 추출 또는 대체 코멘터리 |
| AI 타임아웃 | 응답 지연 | 대기 중단 + 대체 코멘터리 |
| 자격 증명 없음 | API 키 미설정 | 대체 코멘터리 반환 |
| 최소 간격 내 재요청 | 짧은 간격 연속 요청 | 가장 최근 코멘터리 반환(재생성 없음) |
| 캐시 만료 | 보관 기간 경과 | 코멘터리 재생성 |
| 해외 자산 포함 | USD 종목 보유 | KRW 환산 비중 반영하여 코멘터리 생성 |
| 미존재 포트폴리오 | 없는 id | 포트폴리오를 찾을 수 없음 안내 |
| 미인증 요청 | 토큰 없음 | 인증 필요 안내 |
