# SPEC-STOCK-009 — 인수 기준 (Acceptance Criteria)

Given-When-Then 형식. 각 AC는 §3 요구사항(REQ-*)과 tasks.md(TASK-*)에 연결된다.

---

## 피드백 계수 (REQ-FW-001, 002, 005)

### AC-1: 마이그레이션으로 컬럼 추가 (TASK-001)
- **Given** `recommendations` 테이블에 `base_score`·`feedback_score` 컬럼이 없는 상태에서
- **When** 마이그레이션 0012를 적용하면
- **Then** 두 컬럼이 nullable(Numeric(6,3))로 추가되고, 기존 행은 두 값이 NULL이며
  `total_score`는 변경되지 않는다.

### AC-2: 피드백 계수 정규화·클램프 (TASK-002, 008)
- **Given** 특정 종목에 좋아요·싫어요 투표가 누적된 상태에서
- **When** 피드백 계수를 산출하면
- **Then** 계수는 `[-MAX_ADJ, +MAX_ADJ]` 범위 안에 있으며, up이 압도적이면 양수,
  down이 압도적이면 음수를 반환한다.

### AC-3: 신뢰도 가중 — 소수 투표 영향 제한 (TASK-002, 004, 008)
- **Given** 투표 총수가 적은 종목 A와 투표 총수가 많은 종목 B가 같은 up:down 비율을 가질 때
- **When** 두 종목의 피드백 계수를 비교하면
- **Then** 종목 A의 계수 절댓값이 종목 B보다 작거나 같다(표본이 적을수록 조정이 보수적).

### AC-7: 피드백 없음 = 변동 없음 (TASK-002, 008)
- **Given** 특정 종목에 투표가 한 건도 없는 상태에서
- **When** 피드백 계수를 산출하면
- **Then** 계수는 0이고, 조정 점수는 기본 점수와 동일하다.

## 조정 적용 & 파이프라인 (REQ-FW-003, 004, 006)

### AC-4: 조정 점수 범위 클램프 (TASK-004, 005, 008)
- **Given** 기본 점수와 임의의(경계 포함) 피드백 계수가 주어졌을 때
- **When** 조정 점수를 계산하면
- **Then** 결과는 항상 0.0 이상 1.0 이하이다.

### AC-5: 파이프라인 — 피드백 반영 종목 점수 변화 (TASK-005, 009)
- **Given** 후보 종목 중 하나에 다수의 좋아요가 누적된 상태에서
- **When** 추천 파이프라인을 실행하면
- **Then** 해당 종목의 `total_score`(조정 점수)가 `base_score`보다 높아지고, 조정 점수 기준으로
  순위가 산정된다.

### AC-6: 파이프라인 — 저장된 추적 필드 (TASK-005, 009)
- **Given** 피드백 조정이 적용된 추천 결과를 저장할 때
- **When** `recommendations` 행을 조회하면
- **Then** `base_score`(기본)·`feedback_score`(계수)·`total_score`(조정)가 모두 기록되어
  있고, base + 조정량 = total 관계가 성립한다.

### AC-8: 일괄 집계 — N+1 회피 (TASK-003)
- **Given** N개의 후보 종목에 대한 피드백을 집계할 때
- **When** 피드백 일괄 집계 함수를 호출하면
- **Then** 종목 수에 비례한 개별 쿼리가 아닌 단일(GROUP BY) 조회로 모든 종목의 up/down 합계를
  반환한다.

## 스코어 투명성 — 백엔드 (REQ-ST-001, 002, 005)

### AC-9: 상세 응답 — 분해 데이터 포함 (TASK-006, 007, 009)
- **Given** 피드백 조정이 적용된 종목이 있을 때
- **When** `GET /recommendations/{krx_code}`를 호출하면
- **Then** 응답에 4요인 가중 기여도(가중치 × 요인 점수) 목록과 피드백 조정량,
  `base_score`·`feedback_score`가 포함된다.

### AC-10: 하위 호환 — 기존 필드·구 데이터 (TASK-006, 009)
- **Given** `base_score`·`feedback_score`가 NULL인 구 추천 데이터가 있을 때
- **When** `GET /recommendations`·`GET /recommendations/{krx_code}`·`/history`를 호출하면
- **Then** 기존 필드(total_score, sentiment_score 등)는 변경 없이 반환되고, 신규 필드는
  None(또는 생략)으로 응답하며 오류가 발생하지 않는다.

### AC-11: 분해 산술 일관성 (TASK-004, 007, 008)
- **Given** 어떤 종목의 분해 데이터가 주어졌을 때
- **When** 4요인 기여도를 합산하면
- **Then** 합이 기본 점수와 일치하고(부동소수 허용 오차 내), 기본 점수 + 피드백 조정량이
  조정 점수와 일치한다.

## 스코어 투명성 — 프론트 (REQ-ST-003, 004, 005)

### AC-12: 상세 화면 — 분해 시각화 (TASK-010, 012)
- **Given** 분해 데이터가 포함된 종목 상세를 열었을 때
- **When** 상세 화면이 렌더링되면
- **Then** 4요인 가중 기여도가 막대(또는 동등 시각 요소)로 표시되고, 피드백 조정량이 별도
  영역에 표시된다.

### AC-13: 구 데이터 — graceful 렌더 (TASK-010, 011, 012)
- **Given** 분해/피드백 필드가 없는 구 데이터를 표시할 때
- **When** 상세 화면 또는 추천 목록이 렌더링되면
- **Then** 피드백 조정 영역·배지는 생략되고, 화면은 오류 없이 정상 렌더링된다.

### AC-14: 목록 — 피드백 반영 표시 (TASK-011, 012)
- **Given** 피드백 조정이 적용된(base ≠ adjusted) 추천 항목이 목록에 있을 때
- **When** 추천 목록이 렌더링되면
- **Then** 해당 항목에 피드백 반영을 나타내는 배지/툴팁이 표시되어 사용자가 조정 여부를
  인지할 수 있다.
