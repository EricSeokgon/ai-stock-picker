# SPEC-STOCK-038: 시장 시각화 대시보드 (Market Visualization Dashboard)

> Roadmap 시각화(visualization) 계열 SPEC. 분산된 포트폴리오 데이터(가치·섹터·자산구성·벤치마크)를 **하나의 반응형 대시보드 화면**으로 묶어 시각화한다. 신규 지표는 계산하지 않으며, SPEC-035(월별 스냅샷)·SPEC-034(벤치마크 비교)·기존 보유 종목 상세를 **집계·시각화**한다. 자동 매매·실시간 스트리밍은 하지 않는다(영구 제외).

## 1. 개요 (Overview)

### 1.1 기능 설명

투자자는 포트폴리오의 가치 추이·섹터 분포·자산 구성·시장 대비 성과를 **여러 화면을 오가지 않고 한눈에** 보고 싶어 한다. 현재 시스템은 성과(030)·벤치마크(034)·리스크(027)·배당(033)을 각각의 패널/API로 분산 제공할 뿐, 통합 시각화 대시보드가 없다.

SPEC-038은 이 간극을 메운다. 신규 데이터 수집이나 지표 계산 없이 **기존 데이터를 집계·시각화**한다.

- **포트폴리오 가치 시계열 차트** — 총 평가액(KRW)의 시간 추이 라인 차트. 원천은 SPEC-035 월별 스냅샷.
- **섹터 히트맵** — 보유 종목을 섹터별로 묶어, 수익률(%)에 따라 색 강도를 달리하는 히트맵.
- **자산 배분 차트** — 섹터 또는 자산유형(국내/해외)별 구성 비중 파이/도넛 차트.
- **벤치마크 비교 차트** — 포트폴리오 vs 시장 지수(KOSPI 등)의 100 기준 재기준화 다중 라인 차트. 원천은 SPEC-034.

### 1.2 동기 (Motivation)

- **통합 관점**: 분산된 패널을 한 대시보드로 묶으면 의사결정 효율이 높아진다.
- **시각적 직관**: 숫자 테이블보다 차트가 추세·집중도·상대 성과를 빠르게 전달한다.
- **자산 재활용**: 이미 존재하는 스냅샷·벤치마크·보유 상세를 시각화 레이어로 묶어 추가 데이터 비용 없이 가치를 만든다.

본 SPEC은 정보 제공·시각화 지원이며, 실제 매매·실시간 추적을 하지 않는다.

### 1.3 목표 (Goals)

- 설정 가능한 기간(7일/30일/90일/365일)에 대해 포트폴리오 총 평가액 시계열 데이터를 제공한다.
- 보유 종목을 섹터별로 집계하여 현재 평가액과 수익률(%)을 제공한다.
- 보유 종목을 자산유형(국내/해외)별로 집계하여 구성 비중을 제공한다.
- 포트폴리오·벤치마크의 재기준화 시계열을 (SPEC-034 재사용으로) 동일 화면에 제공한다.
- 4종 차트를 반응형 그리드로 렌더하고, 기간 전환·빈 상태·로딩 상태를 제공한다.
- 집계 핵심 로직을 DB·외부 API 없이 테스트 가능한 순수 함수로 분리한다.

### 1.4 기술 스택 (확정·재사용)

- 백엔드: FastAPI + SQLAlchemy + PostgreSQL + Redis. 집계는 numpy/math만 (scipy 금지).
- 프론트엔드: React + **Recharts ^2.14.1**(이미 설치됨).
- 데이터 원천: `portfolio_monthly_snapshots`(0022) + 보유 종목 상세(service.py) + `GET /benchmark/chart`(SPEC-034).
- **신규 DB 테이블·마이그레이션 없음 — 최신 마이그레이션 0024 유지.**

## 2. 환경·가정 (Environment & Assumptions)

- **A1. 가치 시계열의 해상도는 월 단위다.** 원천 `portfolio_monthly_snapshots`는 월별 스냅샷만 보관한다. 따라서 7일/30일 같은 짧은 기간은 데이터 포인트가 0~2개로 희소할 수 있다. 본 SPEC은 일별 시계열을 새로 적재하지 않으며, 기존 스냅샷 범위 내에서만 가치 차트를 구성한다.
- **A2. 벤치마크 비교 차트는 SPEC-034 엔드포인트를 그대로 소비한다.** 본 SPEC은 벤치마크 백엔드를 재구현하지 않는다.
- **A3. 섹터 분류는 `get_sector(krx_code)` 공용 헬퍼를 재사용한다.** 섹터 미상 종목은 "기타/해외" 묶음으로 분류한다.
- **A4. 자산유형은 보유 종목의 `market` 필드로 판별한다.** KRX=국내, NYSE·NASDAQ=해외.
- **A5. 소유권 검증은 `get_portfolio_with_holdings`를 재사용한다.** 미소유 접근은 404로 응답한다(403 아님).
- **A6. 빈 포트폴리오·데이터 부족은 오류가 아니다.** 빈 차트 데이터(빈 배열·빈 상태 마커)로 정상 응답한다.

## 3. 기능 요구사항 (Functional Requirements, EARS)

### REQ-DASH-001 — 가치 시계열 데이터 (Event-driven)

WHEN 사용자가 특정 기간을 지정하여 포트폴리오 가치 시계열을 요청하면, THE 시스템 SHALL 해당 기간에 속하는 월별 스냅샷을 시간 순으로 정렬한 (날짜, 총 평가액) 데이터 집합을 제공한다.

### REQ-DASH-002 — 섹터 집계 데이터 (Event-driven)

WHEN 사용자가 포트폴리오 섹터 집계를 요청하면, THE 시스템 SHALL 보유 종목을 섹터별로 묶어 섹터별 현재 평가액과 수익률(%)을 제공한다.

### REQ-DASH-003 — 자산유형 배분 데이터 (Event-driven)

WHEN 사용자가 포트폴리오 자산유형 배분을 요청하면, THE 시스템 SHALL 보유 종목을 자산유형(국내/해외)별로 묶어 각 유형의 평가액과 구성 비중(%)을 제공한다.

### REQ-DASH-004 — 벤치마크 비교 데이터 (Ubiquitous, 재사용)

THE 시스템 SHALL 동일 기간에 대해 포트폴리오와 시장 벤치마크의 100 기준 재기준화 시계열을 (기존 벤치마크 비교 기능을 통해) 제공한다.

### REQ-DASH-005 — 대시보드 UI 렌더 (Event-driven)

WHEN 사용자가 대시보드 화면에 진입하면, THE 시스템 SHALL 가치 시계열·섹터 집계·자산유형 배분·벤치마크 비교 4종 차트를 반응형 그리드 배치로 표시한다.

### REQ-DASH-006 — 기간 선택 (Event-driven)

WHEN 사용자가 기간 선택(7일/30일/90일/365일)을 변경하면, THE 시스템 SHALL 변경된 기간에 맞추어 가치 시계열 및 벤치마크 비교 차트를 다시 표시한다.

### REQ-DASH-007 — 빈 상태 (Unwanted)

IF 선택한 기간에 표시할 스냅샷·보유 데이터가 없으면, THEN THE 시스템 SHALL 오류 대신 해당 차트에 의미 있는 빈 상태 안내를 표시한다.

### REQ-DASH-008 — 로딩 상태 (Event-driven)

WHEN 대시보드 데이터를 조회하는 중이면, THE 시스템 SHALL 각 차트 영역에 로딩 표시를 노출한다.

### REQ-DASH-009 — 소유권 보호 (Unwanted)

IF 사용자가 자신이 소유하지 않은 포트폴리오의 대시보드 데이터를 요청하면, THEN THE 시스템 SHALL 해당 포트폴리오의 존재를 드러내지 않는 방식으로 접근을 거부한다.

## 4. 비기능 요구사항 (Non-Functional Requirements, EARS)

### REQ-DASH-NFR-001 — 계산 라이브러리 제약 (Unwanted)

IF 대시보드 집계에 수치 계산이 필요하면, THEN THE 시스템 SHALL scipy를 사용하지 않고 numpy 및 표준 수학 연산만으로 계산한다.

### REQ-DASH-NFR-002 — 순수 함수 분리 (Ubiquitous)

THE 시스템 SHALL 대시보드 집계 핵심 로직을 데이터베이스 및 외부 API 의존 없이 테스트 가능한 순수 함수로 분리하여 제공한다.

### REQ-DASH-NFR-003 — 소유권 위반 응답 (Unwanted)

IF 소유권 위반 요청이 들어오면, THEN THE 시스템 SHALL 권한 부재를 자원 부재와 구분되지 않게 처리하여 자원의 존재 여부를 노출하지 않는다.

### REQ-DASH-NFR-004 — 재사용 가능한 차트 컴포넌트 (Ubiquitous)

THE 시스템 SHALL 대시보드 차트 컴포넌트를 외부 입력(props)으로 구동하며 특정 포트폴리오 식별자를 내부에 고정하지 않는 형태로 제공한다.

### REQ-DASH-NFR-005 — 기간 파라미터 서버측 검증 (Unwanted)

IF 허용되지 않은 기간 값이 요청되면, THEN THE 시스템 SHALL 해당 요청을 거부하고 허용된 기간 값만 처리한다.

## 5. Exclusions (What NOT to Build)

본 SPEC이 **명시적으로 제외**하는 항목 (범위 통제):

- **자동 매매·주문 실행** — 규제·책임 리스크로 영구 제외.
- **실시간 WebSocket 차트 갱신** — 폴링/요청 기반만. 실시간 틱 스트리밍 제외.
- **캔들스틱·기술적 지표 차트**(이동평균·RSI 등) — SPEC-023 영역.
- **신규 데이터 수집/적재** — 기존 스냅샷·벤치마크·보유 데이터만 사용. **일별 가치 시계열 적재 잡 제외**(가치 차트는 월별 해상도).
- **PDF/이미지 내보내기** — SPEC-035 리포트(CSV/JSON) 영역, 본 SPEC은 화면 시각화만.
- **벤치마크 비교 백엔드 재구현** — SPEC-034 `GET /benchmark/chart` 재사용.
- **신규 DB 테이블·마이그레이션** — 0024 유지.
- **신규 지표 계산**(샤프·알파·베타·MDD 등) — 기존 서비스 결과를 시각화만.
- **사용자 정의 차트 구성·위젯 배치 저장** — 고정 4종 그리드만.
